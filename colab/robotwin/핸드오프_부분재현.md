# 핸드오프: RoboDawn 기준선 부분 재현 (Colab L4 두 대, 밤새 무인 실행)

이 문서를 받은 에이전트는 사용자가 자는 동안 아래 실험을 끝까지 돌리고, 결과를 정리한 뒤 VM을 끄고, 마지막의 "보고 양식"으로 결과를 남긴다. 사용자에게 중간에 물어볼 수 없다. 판단이 필요한 곳은 이 문서의 규칙대로 하고, 규칙에 없는 상황이면 안전한 쪽(멈추고 기록)을 택한다.

## 1. 목표

공개된 RoboDawn 하네스로 Gemini 3.8 Flash의 RoboTwin 2.0 성공률을 재현한다. 10개 과제 × 10 에피소드를 같은 seed로 돌려, 사이트에 공개된 원 결과(같은 100개 에피소드에서 56/100 성공)와 비교한다.

- 재현 판정: `scripts/compare_robodawn.py`의 전체 성공률 차이가 95% 구간 안이면 "원 결과와 일치", 밖이면 "차이 있음". 둘 다 정상적인 결과다. 숫자를 좋게 만들려고 설정을 바꾸지 않는다.
- 부산물: 원 방식의 턴당 지연을 standard 요금으로 잰 기준 두 에피소드.

## 2. 이미 준비된 것 (사용자가 자기 전에 확인)

- 저장소: GitHub `https://github.com/NiceTry3675/LIBERO-research`의 `main`을 이 컴퓨터에 받아 두었다(`git clone` 또는 `git pull`). 이 문서가 들어간 커밋 이후 상태여야 한다(`git log --oneline -5`에 "부분 재현 핸드오프 문서"가 있는지 확인).
- Colab CLI(`colab`, 0.7.4)가 설치되고 사용자 Google 계정으로 로그인되어 있다. `colab usage`가 잔액을 보여야 한다(2026-10-08 기준 약 623 컴퓨트 단위).
- Vertex AI 서비스 계정 키(JSON) 파일. 경로는 사용자가 `GOOGLE_APPLICATION_CREDENTIALS`로 알려 주거나 저장소 루트에 둔다. 이 파일은 gitignore 대상이며 **내용을 읽거나 출력하거나 커밋하지 않는다.** 스크립트가 파일째 업로드한다.
- 선택: 저장소 루트 `.env`의 `HUGGINGFACE_API_KEY`(에셋 내려받기 속도 제한 완화). 없어도 된다. `.env`의 다른 값은 쓰지 않는다.
- 로컬에 필요한 것: bash, python3(표준 라이브러리만), tar. GPU는 필요 없다.

시작 전에 확인하고, 하나라도 없으면 실험을 시작하지 말고 보고 양식에 무엇이 없었는지만 적는다.

```bash
git log -1 --format='%h %s'
colab usage
colab sessions
test -f "$GOOGLE_APPLICATION_CREDENTIALS" && echo key-ok
```

## 3. 절대 지킬 것

1. **실험 조건을 바꾸지 않는다.** `third_party/robodawn`(하네스), `robodawn_site/`(수집 기록, seed, manifest), `scripts/run_robodawn_baseline.py`의 요청 조건(모델, 추론 기본값, 8000토큰, 45턴, 카메라, temperature 미전송, flex)을 수정하지 않는다. 설치 스크립트의 환경 문제를 고치는 것은 허용하되, 고친 내용을 보고에 적는다.
2. **키를 보호한다.** 서비스 계정 키와 `.env`의 값을 출력, 로그, 커밋, 실행 코드에 넣지 않는다. `colab exec`로 보내는 코드는 세션 기록에 남는다.
3. **VM을 반드시 끈다.** 정상 종료든 중단이든 마지막에 `bash colab/robotwin/subset.sh stop`(robotwin)과 `bash colab/robotwin/subset.sh --session robotwin2 stop`을 실행하고 `colab sessions`가 비었는지 확인한다. 켜 둔 VM은 시간당 컴퓨트 단위를 계속 쓴다.
4. **예산.** 예상은 Colab 약 35 컴퓨트 단위, Vertex 약 $20이다. Colab 사용이 80 컴퓨트 단위를 넘거나, 비교 출력의 대략 비용(`rough cost`)이 $50을 넘으면 실행을 멈추고(VM 종료) 보고한다.
5. **커밋하지 않는다, push하지 않는다.** 결과 보고서 파일은 만들되 커밋은 사용자가 정한다.
6. OpenRouter를 쓰지 않는다. robodawn.top에 접근하지 않는다(필요한 기록은 `robodawn_site/`에 있다).

## 4. 순서

모든 명령은 저장소 루트에서 실행한다. VM 쪽 작업은 전부 백그라운드로 돌고, `status`로 확인한다. 기다릴 때는 10~15분 간격으로 확인한다(그보다 자주 볼 필요 없다).

### 4-1. VM 두 대 설치 (약 1시간, 동시에)

```bash
bash colab/robotwin/launch.sh --textures
bash colab/robotwin/launch.sh --textures --session robotwin2
```

- 두 번째 세션이 만들어지지 않으면(동시 세션 제한 등) 오류 문구를 기록하고 **한 대로 진행한다**(4-5의 단일 VM 방법).
- 진행 확인:
  ```bash
  echo 'print(open("/content/bootstrap.log").read()[-1500:])' | colab exec -s robotwin
  ```
  `BOOTSTRAP_DONE`이 나오면 끝이다. `BOOTSTRAP_FAILED`면 해당 단계 로그(`/content/setup_env.log`, `/content/install_rt.log`, `/content/download_assets.log`) 끝을 보고 환경 문제면 고쳐서 다시 설치한다. 같은 VM에서 `install_rt.sh`를 다시 돌리면 이미 있는 폴더 때문에 실패하므로, 세션을 끄고 새로 띄우는 편이 깔끔하다.
- 확인할 줄: `install_rt.log`의 `STEP_CLONE_OK 96c1feab...`(RoboTwin 고정 커밋)와 `STEP_ARCH 8.9`(L4).

### 4-2. 준비 (각 VM, 약 10분)

```bash
bash colab/robotwin/subset.sh setup --key "$GOOGLE_APPLICATION_CREDENTIALS"
bash colab/robotwin/subset.sh --session robotwin2 setup --key "$GOOGLE_APPLICATION_CREDENTIALS"
bash colab/robotwin/subset.sh status
bash colab/robotwin/subset.sh --session robotwin2 status
```

`/content/prepare.log` 끝에 `ROBODAWN_READY`가 나와야 한다. 그 앞 줄에 점검 결과(seed 500, 시연 500, 프롬프트 일치 true)가 찍힌다. 일치하지 않으면 멈추고 보고한다.

### 4-3. 시험 실행: flex (robotwin에서만, 약 30~60분, 약 $1)

```bash
bash colab/robotwin/subset.sh smoke
bash colab/robotwin/subset.sh status
```

`/content/smoke_flex.log`에 `SMOKE_DONE`이 나오면 `status`의 `check` 줄 두 개가 모두 `ok`여야 한다. 하나라도 오류면 **본 실행으로 가지 않는다.** 오류 내용, 해당 과제의 로그를 보고에 적고 VM을 끈다.

시험 실행이 도는 동안 GPU 메모리를 한 번 기록한다(보고용, 동시 실행 수는 바꾸지 않는다).

```bash
echo 'import subprocess; print(subprocess.run("nvidia-smi --query-compute-apps=pid,used_memory --format=csv; nvidia-smi --query-gpu=memory.used,memory.total --format=csv", shell=True, capture_output=True, text=True).stdout)' | colab exec -s robotwin
```

통과하면 시험 결과를 이 컴퓨터로 받는다. 두 번째 VM은 이 결과를 근거로 시작한다.

```bash
bash colab/robotwin/subset.sh fetch
```

`fetch` 출력의 비교표에서 다음을 기록한다: `cut off by the token budget` 수, 캐시 비율, 호출 시간 중앙값, 대략 비용.

### 4-4. 본 실행 (약 5~6시간)

```bash
bash colab/robotwin/subset.sh run --part 1/2
bash colab/robotwin/subset.sh --session robotwin2 run --part 2/2
```

- 동시 실행 수는 기본값 3을 쓴다. 바꾸지 않는다.
- 1/2 몫은 adjust_bottle, click_bell, lift_pot, place_a2b_right, place_empty_cup, place_fan, 2/2 몫은 handover_block, move_can_pot, open_laptop, place_object_stand다.
- 두 번째 VM의 `run`이 "no passed flex smoke checks"로 거부되면 4-3의 `fetch`를 먼저 했는지 확인한다.

### 4-5. 한 대로만 진행할 때

두 번째 세션을 못 만들었으면 4-4 대신:

```bash
bash colab/robotwin/subset.sh run
```

예상 시간은 약 11시간이다. 아침까지 다 못 끝나도 괜찮다. 끝난 에피소드까지 받아서 보고한다.

### 4-6. 지켜보기

30~45분마다:

```bash
bash colab/robotwin/subset.sh status
bash colab/robotwin/subset.sh --session robotwin2 status
colab usage
```

2~3시간마다 결과를 받아 둔다(VM이 사라져도 그때까지는 남는다):

```bash
bash colab/robotwin/subset.sh fetch
bash colab/robotwin/subset.sh --session robotwin2 fetch
```

대응 규칙:

| 상황 | 할 일 |
| --- | --- |
| `status.tsv`에 `failed` 샤드가 있음 | 해당 샤드 로그 끝을 본다. VM에서는 `/content/branchlab/outputs/robodawn/subset_flex_<세션>/<task>__<start>.log`, 받은 뒤에는 `outputs/robodawn_colab/<세션>/robodawn/subset_flex_<세션>/`에 있다. 조건 점검 실패(`errors`)면 내용을 기록한다. 일시적 오류(네트워크, 429 지속, watchdog 종료)면 같은 `run` 명령을 다시 실행한다. 끝난 에피소드는 건너뛴다. 같은 샤드가 두 번 실패하면 더 다시 돌리지 않고 기록만 한다. |
| 조건 점검 오류가 seed·시연·모델·트래픽 종류 불일치 | 실행 조건이 깨진 것이다. 그 VM의 실행을 멈추지는 말되(다른 샤드는 별개), 보고 맨 위에 적는다. |
| 로그에 429/5xx 재시도가 계속 보임 | 하네스가 최대 15분까지 재시도한다. 그대로 둔다. 한 시간 넘게 진척이 없으면 VM 하나만 남기고 다른 하나의 실행을 멈춘다(`subset.sh --session robotwin2 stop`은 VM까지 끄므로, 그 전에 `fetch`). |
| VM이 사라짐(`colab sessions`에 없음) | 마지막 `fetch`까지의 결과는 남아 있다. 남은 시간이 3시간 이상이면 같은 이름으로 다시 설치(4-1, 4-2)하고 같은 `run --part` 명령을 다시 실행한다. 이미 받은 에피소드를 다시 돌리게 되지만 비교는 한 번만 센다. 3시간 미만이면 다시 띄우지 않는다. |
| 예산 한도(3항) 초과 | 두 VM 모두 `fetch` 후 `stop`. |

### 4-7. 지연 기준: standard (본 실행이 끝난 뒤, 약 30~60분)

먼저 끝난 VM이 아니라 **robotwin**에서 한다(시험 실행 결과가 있는 VM).

```bash
bash colab/robotwin/subset.sh smoke --tier standard
```

`/content/smoke_standard.log`에 `SMOKE_DONE`이 나오면 끝이다. 조건 점검은 standard 기준(`ON_DEMAND`)으로 따로 한다.

### 4-8. 마무리

1. 두 VM의 `subset.log`에 `SUBSET_DONE`이 나왔는지 확인한다(또는 아침이 되어 멈춘다).
2. 이미지와 영상까지 받는다(나중에 Clef 오프라인 시험에 쓴다). 크기가 커서 시간이 걸린다.
   ```bash
   bash colab/robotwin/subset.sh fetch --full
   bash colab/robotwin/subset.sh --session robotwin2 fetch --full
   ```
   `--full`이 디스크나 시간 문제로 실패하면 가벼운 `fetch`라도 받는다.
3. 최종 비교를 저장한다.
   ```bash
   python3 scripts/compare_robodawn.py --tier flex --runs outputs/robodawn_colab/*/robodawn > outputs/robodawn_colab/compare_flex.txt
   python3 scripts/compare_robodawn.py --tier standard --runs outputs/robodawn_colab/*/robodawn > outputs/robodawn_colab/compare_standard.txt
   ```
4. VM을 끈다(3항). `colab sessions`가 비었는지, `colab usage`의 사용률이 0인지 확인한다.
5. 아래 보고서를 `reports/RoboDawn_부분재현_결과.md`로 쓴다.

## 5. 보고 양식

`reports/RoboDawn_부분재현_결과.md`에 다음을 쓴다. 사실만 쓰고, 해석은 짧게 구분해서 쓴다.

```
# RoboDawn 부분 재현 결과 (YYYY-MM-DD)

## 요약
- 재현 판정: 일치 / 차이 있음 / 미완료 (완료 에피소드 n/100)
- 전체 성공률: 우리 x% vs 사이트 y% (차이, 95% 구간)
- 에피소드 일치율
- 조건 점검 실패: 없음 / 있음(내용)

## 과제별
(compare_flex.txt의 과제별 표를 그대로)

## 실행 조건 확인
- RoboTwin 커밋, STEP_ARCH, 두 VM 사용 여부(한 대였다면 이유)
- flex 트래픽 비율, 응답 예산에 잘린 응답 수, 캐시 비율
- 프로세스당 GPU 메모리(4-3에서 잰 값)

## 시간과 비용
- 시작·종료 시각, 단계별 소요(설치, 시험, 본 실행, standard)
- 호출 시간: flex 중앙값/90%, standard 중앙값/90% (compare_standard.txt)
- Colab 컴퓨트 단위 사용량(시작·종료 잔액 차이), Vertex 대략 비용

## 문제와 조치
- 실패한 샤드, 재실행, VM 재설치, 설치 스크립트 수정 내역 등

## 파일
- 결과 위치: outputs/robodawn_colab/<세션>/robodawn/
- 비교: outputs/robodawn_colab/compare_flex.txt, compare_standard.txt
```

## 6. 참고

- 스크립트 설명: `colab/robotwin/README.md`의 "RoboDawn 기준선 재현 준비", "CLI로 부분 재현 돌리기".
- `subset.sh` 사용법: `bash colab/robotwin/subset.sh`(인자 없이)로 도움말을 본다.
- 에피소드 하나는 10~40분 걸린다. flex 요청은 대기열을 거쳐 한 번에 1~2분 걸리기도 한다. 하네스의 요청 제한은 900초, watchdog는 1200초다.
- 원 결과와 다르게 나오는 것은 실패가 아니다. 조건을 지키고 그대로 보고하는 것이 이 작업의 목적이다.
